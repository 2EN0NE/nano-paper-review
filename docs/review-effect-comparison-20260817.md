## 四、关键发现：重试机制成为兜底主力

本次 40 篇 × 2 个 agent 步骤（06/07）= 80 次 LLM 调用，实测：

| 指标 | 数值 |
|---|---|
| 首次输出非 JSON（触发重试） | **45/80（56.2%）** |
| 06-direct-scoring 重试 | 25 次 |
| 07-indirect-scoring 重试 | 22 次 |
| 重试后成功（反馈注入生效） | **42/45（93.3%）** |
| 重试耗尽（最终 error） | 3 篇（06 的 02-13 / 05-21 / 08-06） |

**结论**：

- 新代码的「非 JSON → 重试 → 反馈注入」机制是**本次效果达成的关键**——在 reasoning 模型（deepseek-v4-pro, high）首次 JSON 失败率高达 56% 的情况下，靠重试把最终结构化成功率救回到 90%。
- 旧代码没有重试机制，非 JSON 直接静默为 `raw_output`，结构化率为 0。

## 五、自我审查：还有什么可改进的（仅分析，不实施）

### 5.1 根因是模型选择，重试是治标

- **现象**：reasoning 模型（`PI_REASONING_LEVEL=high`）首次 JSON 失败率 56.2%，是本次最大的质量波动源。3 篇最终 error（02-13、05-21 积木、08-06 ZGC）都是 reasoning 模型「走神」输出非 JSON 且重试仍失败。
- **建议方向**：`pipeline.yaml` 的 `review` phase 已有预留的 `agent.model` 覆盖位（注释里写明「特征抽取用 non-reasoning 更稳定」），打分步（06/07）同样应切换到 non-reasoning 模型从根源降低失败率，而非依赖重试兜底。重试每次额外消耗 30-100s + 一次 LLM 调用，成本不低。

### 5.2 重试耗尽后的降级仍偏「粗糙」

- 3 篇 error 的 06 最终走 `raw_output` 兜底，08 用正则从 markdown 第三列提取 rationale——但实测这 3 篇提取结果 **6 维全空**（`rationale_missing` 全 6 维），最终 rationale 全空、仅靠分数兜底。
- **分析**：说明这些篇的 `raw_output` 形态不是标准 markdown 表格（reasoning 模型输出的是自由文本或残缺表格），正则兜底失效。若要救回，需要更鲁棒的兜底（如针对自由文本的二次 LLM 抽取），或接受「标记为缺证据」的现状（当前 evidence 已如实标记，不误导）。

### 5.3 跳过的软文未纳入 evidence 统计

- Q1 的 01-17（技术年货 900+ 页电子书）被 06 判为 skipped，08 也标记了 evidence 缺证据。但这类「软文/合集」类文章本身不适合六维评分，建议在 subject 层面前置识别（而非靠 06 评分时跳过），避免浪费一次 LLM 调用。

### 5.4 跨季度参考生效后，检索相关性未验证

- 池提升修复后，Q2/Q3 的 05-batch-search 能检索到历史季度的论文作参考。但本次未验证这些跨季度参考的**相关性**（是否真的相似、是否误导打分）。旧代码 history 恒空时，06 的 rationale 里会注明「无相似论文可比对」；新代码有了参考后，若参考不相关反而可能引入噪声。建议抽查 Q2/Q3 几篇的参考质量。

### 5.5 rationale 的「好不好」仍留白

- 本次修改（及之前的决策）只判定 rationale「有没有」，不判「好不好」（内容空洞如「论证充分」仍算有证据）。这是刻意留到下一阶段的。抽查显示结构化 rationale 质量明显提升（引用具体章节号、数字、与参考对比），但「空洞但非空」的边界仍需后续用更强的判据（如证据引用密度、具体性检查）来把关。

## 六、结论

**本次「增强提取结构化原因」的修改效果显著，是质的提升：**

1. **结构化输出 0% → 90%**（36/40 篇），每篇拿到 6 维 `{score, rationale}` + `tags`，这是旧代码完全缺失的能力。
2. **索引闭环打通**：tags 写回 0 → 36 篇，池提升 0 → 40 篇，history 池从恒空到满载，跨季度历史参考从 Q2 起真正生效。
3. **可观测性从无到有**：evidence 字段级降级标记，把「缺证据」从静默变成精确到篇+维度的显式告警。
4. **重试机制是隐形功臣**：在 reasoning 模型 56% 首次失败率下，靠「非 JSON → 重试 → 反馈注入」把最终成功率救到 90%。

**最值得后续投入的方向**（按优先级）：① 打分步切换 non-reasoning 模型从根源降低 56% 的失败率；② 验证跨季度参考的相关性；③ 补 rationale「好不好」的内容质量判据。
